# 文风与语言约定

> **这份文件管什么**：攻略正文的**用词** —— 哪些位置必须书面、哪些位置可以说人话、要避开哪些语言毛病。
> **不管什么**：结构怎么搭（见 `content-model.md`）、视觉怎么排（见 `design-system.md`）。
> **怎么用**：写文案时对照；**结构位置写完后必须逐项核对本文件的术语表**。这是最容易被忽略的一步。

## 1. 一句话

**一份攻略要同时做到"专业"和"有人味"。这两件事不冲突 —— 分层处理。**

- **结构位置**（读者用来"找路"的文字）：**必须书面语**。
- **正文位置**（读者用来"下决心"的说明）：**当然可以说人话**。

> ⚠️ **两类的边界不清，就是上一版翻车的原因**（Q30 实测）：`为什么这样安排`、`不来等于没来`、`这座城市怎么玩才不累` 三处**都是结构位置，却写成了口语**。读者扫目录时看到的是三个问句和一句口号 —— 找不到落点，像聊天记录，不像交付物。

## 2. 结构位置：必须书面语

**结构位置 = 读者用来「找路」的文字。** 它的职责是**可检索、可预测、可速读**，不是表达情绪。

**完整清单（凡属以下位置，一律书面语，无例外）**：

| 类别 | 具体位置 |
|---|---|
| **标题族** | 章节标题 / 小节标题 / 卡片标题 / 块标题 / **口诀（`.jingle`）** |
| **导航族** | 顶层目录项 / 折叠面板摘要 / 按钮文案 / 链接文案 |
| **字段族** | 表格表头 / 字段名（`.q` `.lb` `.tl` `.k`）/ 分组名 / 页脚标签 |
| **封面族** | 封面主标题 / 副标题 |
| **标签族** | 倾向徽标 / 核验行 / **避坑严重度点（暗红 = 必读 / 暗黄 = 提示）** / 事实芯片的字段名 / 规避分组名 |
| **图内族** | 脑图节点文字 / 时间轴标签 |

### 写法要求

1. **用名词短语或动宾短语**：`安排思路` / `预算构成` / `出发前必须做的事` / `一句话总结`。
2. **不用疑问句**：疑问句是"聊天"，不是"条目"。
3. **不用人称**（你 / 我 / 我们 / 大家）：攻略是交付物，不是对话。
4. **不用口号与比喻**：`不来等于没来` / `一眼千年` / `此生必去` 属于宣传语，不携带信息。
5. **同一概念全篇同一个词**（见 §8 术语表）。

### 一条可执行的判据（写完后逐条过）

> **把这一条单独摘出来，它能不能当「检索词」？**
>
> - `安排思路` → ✅ 能。读者搜"思路"能找到它，它是一条**条目**。
> - `为什么这样安排` → ❌ 不能。这是**问句**，摘出来不像目录项。
>
> **再问一句：它携带信息了吗？**
>
> - `不可替代` → ✅ 说了"这个景点没有替代品"，读者据此能下判断。
> - `不来等于没来` → ❌ 是情绪。"没来"本身**没有指向任何具体的事**。

## 3. 正文位置：可以说人话

**正文位置 = 读者用来「下决心」的说明。** 这里**保持口语反而更好**，**不要**"书面化"。

| 位置 | 说明 |
|---|---|
| 景点的**一句话总结**（`.why`） | 结论句，要短、要有判断。**它本身就是"值得去的理由"** —— 不再另设字段 |
| **小提示**（`.spot-tip` 的那一行） | 一句话说清"什么情况下会失望 / 要提前做什么"，**不铺开成段落** |
| **避坑条目的说明**（`.pd`） | 讲清"会怎样、怎么绕" |
| **每日动线说明**（`—— {说明}`） | 讲清这一段具体怎么走 |
| **餐饮店家的一行说明** | 讲清"招牌 / 为什么选它 / 顺不顺路"，见 `content-model.md` §5 |
| **提醒行**（`.say`） | 一句行动提示（"以现场票价为准""出发前再看一次天气"）——**提醒是给人的动作** |
| **城市特点卡的正文** | 讲这座城市怎么运转 |

> **理由**：攻略一半的价值在"有人真的替你想过"。
> **把这些句子改成四平八稳的书面语，攻略就变成了说明书。**

### 但"生动"有边界

> **生动是为了让信息好懂，不是为了让人激动。**
>
> **判据**：删掉那句形容词 / 比喻，**信息有没有损失**？
> - **有损失** → 它是信息，留着。（`带长辈绝对不能走的那段台阶` —— 删掉"带长辈"，就不知道限制条件了。）
> - **没损失** → 它是情绪，删掉。（`此生必去` —— 删掉之后什么都没少。）
>
> ⚠️ **生动只在正文里用。一旦挪到结构位置（标题 / 字段名 / 标签），它就变成噪音。**

## 4. 三处必须"分行罗列"的信息卡

> **Q39 用户判定**：行程总览里的 **气温、必带、分人群建议**三处 **"话术不简略"** ——
> 而且是**靠句子切断换行**，不是真的分行。

这三处的共同点：**读者是来"逐项勾对"的，不是来读段落的。** 所以它们各有硬格式：

| 位置 | 硬格式 | ❌ 实际出现过的写法 | ✅ 应写成 |
|---|---|---|---|
| **天气**（标题写「天气」，**别写成气温**） | **恰好三行**：白天 / 夜间 / **天气总结**。数值只给前两行，第三行只给晴雨与体感结论。**不加第 4 行小字** | 标题写「气温」；写成四行（多一行"常年同期参考…"的提醒）；第三行是「降水」 | `白天 25–30℃` / `夜间 18–22℃` / `天气总结 多晴少雨，早晚偏凉` |
| **必带** | **分行罗列物品**（模板 `<ul class="bring">`，**一行一件**）。物品名用 `<b>` 加重 | 一句话里用逗号串起五样东西，靠窄屏自己折行 | 每行 `雨衣 / 薄外套 / 防蚊液` 各占一行，**一行只放一到两件** |
| **分人群建议** | **分行**，**一行一类人**（带长辈 / 带孩子 / 摄影 / 徒步），每行 ≤20 字 | 一段话里讲完三类人 | 每行开头 `<b>` 写人群，后面跟一句限制条件 |

**判据**：**读者能不能一眼扫完、并逐项勾对？**
- 扫一眼就能数出"带了几样东西" → 合格。
- 要读完一整句才知道里面提过三样东西 → 不合格。

> ⚠️ **"靠句号 / 逗号切断来换行"不算分行。** 窄屏折行由屏幕宽度决定，正文里那句话在自己的窗口里看仍是**一整段**。
> 真正要的是**语义上的列表**：一项一个 `<li>`。

> 🔧 **Q40 用户判定**：「天气」卡 **"还是多了"** —— 三行之外**不准再加第 4 行小字**。
> 被删掉的是「常年同期参考，不是预报；出发前再看一次」这句。**删它的理由不是"太长"，是角色错位**：
> 它是一条**给读者的提醒**（该干什么），却塞进了**信息卡**（用来勾对的清单）——
> 提醒归 `.say` 的位置（见 §7），信息卡只装"要勾对的东西"。

## 5. 口诀化：游玩要点怎么写

> **Q39 用户判定**：行程全貌的游玩要点 **"字太多、没分行，读着累"** → 改**口诀化**。
> 🔧 **Q40 用户判定**：第一版口诀 **"太简略看不懂，这四句目前都不是人话"** ——
> 我把「好记」执行成了「缩写」，造出一批**只有作者懂的暗语**（地=景点 / 店=住宿 / 爸妈=老人）。
> **这是口诀最容易犯的错，也是本节最重要的一条规则。**

**口诀 ≠ 把字数压短，更 ≠ 自造缩写。** 判据是**好记**，前提是**一眼就懂**。

| 要求 | 说明 |
|---|---|
| ★ **用常用词，禁止自造缩写** | 缩写只有写的人懂。**单字简称（地 / 店 / 爹妈）一律不许用** —— 见下方对照表 |
| **长度** | **6–14 字**（两句，每句 3–7 字）。**"短"和"看得懂"冲突时，选看得懂** |
| **结构** | **两顿对称**（`{前 5 字}，{后 5 字}`），读起来有节奏 |
| **内容** | 必须是**一个可执行的要点**，不是情绪（❌ `美景不虚此行`；✅ `早班船，少排队`） |
| **说明行** | 口诀下方再给 **≤60 字** 的说明，写清"为什么"和"怎么用" |

### ★ 缩写对照表（Q40 抓到的四个真实反例）

| ❌ 自造写法（实测产物） | 读者实际会怎么想 | ✅ 改成 |
|---|---|---|
| `三块地，两换店` | "地"是什么？地块？地点？ | **`景点分三块，住宿换两次`** |
| `陡的不给爹妈` | "爹妈"是口语，放在标签位置像玩笑 | **`台阶太陡的，别排给老人`** |
| `贴水坐筏，坐着坐船` | 两个"坐"绕在一起，读不出在对比什么 | **`竹筏贴水看，游船坐着看`** |
| `先抢漓江，再抢遇龙` | 抢票还是抢位？"遇龙"指哪个点？ | **`先抢漓江票，再抢遇龙河`** |

> **判据**：**把口诀念给一个没看过这份攻略的人听，他能不能复述出你替他做的那个决定？**
> 不能 → 缩写太多，展开。
>
> ⚠️ **"加长"不等于"啰嗦"** —— 上表右侧四句都在 **11–12 字**，比左侧还长，
> 但每个词都是日常词，所以**更好记**。**好记来自"每个词都认识 + 有节奏"，不来自字少。**

**例**（同一件事的三种写法）：

| 写法 | 结果 |
|---|---|
| `建议尽早出发，因为漓江竹筏上午人少、光线也更好` | ❌ 是一句话，不是口诀 |
| `早点去，人少` | ❌ 太瘪，且没说清多早、去哪 |
| **`早班船，少排队`** + 说明 `7:30 前上船，队伍短一半，江面还有晨雾。` | ✅ 好记 + 可执行 + 一眼懂 |

> 口诀**也在结构位置上**（见 §2）—— 用名词 / 动宾短语，不用疑问句、不用人称、不用口号。

## 6. 结构位置的黑名单

以下都是**实测产物里真实抓到**的问题，**不得再出现**：

| 位置 | ❌ 实际出现过的写法 | ✅ 应写成 | 违反了什么 |
|---|---|---|---|
| 总览小节标题 | `为什么这样安排` | **`安排思路`** | 疑问句 |
| 倾向分组名 | `必去 · 不来等于没来` | **`必去 · 不可替代`** | 口号，不携带信息 |
| 倾向分组名 | `值得 · 有明显收获` | **`值得 · 有明确收获`** | 口语（"明显"→"明确"） |
| 倾向分组名 | `可选 · 有时间去，没时间不亏` | **`可选 · 非必需`** | 句子当标签，无信息量 |
| 景点卡字段名 | `值得吗` / `代价是什么` / `值得的理由` | **`一句话总结`**（一个字段够） | 疑问式 / 字段冗余 |
| 景点卡字段名 | `妙计` | **并进 `小提示`，不再单设字段** | 字段冗余（Q39 收紧） |
| 避坑严重度 | `会毁行程` / `体验提示`（旧文字徽标） | **不用文字标签** —— 只在标题前放一个 8px 点（暗红 = 必读 / 暗黄 = 提示） | 文字标签抢占标题注意力（Q39 / Q42 两次收紧） |
| 每日理由行 | `为什么这么排：` | **`安排思路：`** | 疑问句 |
| 折叠面板摘要 | `被排除的选项 · 为什么不去` | **`已排除的选项 · 不去的理由`** | 疑问句 |
| 提醒行 | `妙计：`（冒号前缀） | **`.say`** 里直接写事，**不加字段名前缀** | 用冒号替代字段名 |
| 行程全貌小节 | `{城市}这座城市怎么玩才不累` | **`{城市}游玩要点`** | 疑问句 + 人称 |
| 事实芯片 | `{指标} {值}`（自定义字段名） | 字段名**限字典**（见 `design-system.md` §6） | 字段名不受控 |
| 章节导语 | `这一页看完就能走完整个行程 —— 值不值得去，给答案；怎么去，给材料` | **整段删除** | 元说明（描述自己的结构） |
| 图位标题 | `今日动线 · 真实道路走向（点位与顺序示意，非导航级）` | **`今日动线`**（诚实命名下沉到图下 `.rfoot`） | 元说明：**用文案复述图里画了什么**（"当天 3 个点：A → B → C"图自明） |
| 小红书入口文案 | `景点攻略` / `拍照攻略` / 含「小白出片」的词 | **`小红书·游玩攻略`** / **`小红书·拍照参考`**（**不写景点名** —— 名字一长就撑成两行；搜索词仍是 `{景点名} 游玩攻略`） | 用**自己的制作思路**当读者文案；Q42 再收紧：按钮文案固定化 |

> **章节导语已废止**（Q30）：章节 = 序号药丸 + 标题，**直接进内容**。
> 这类文字**是写给制作者的，不是写给读者的** —— 它在页面上占地方，还把"这份攻略该怎么用"混进正文；读者点开目录就知道要看哪一节。

**三类句式禁令（一句话记住）**：

1. **疑问句不进结构位置。**（"为什么…" / "…吗" / "怎么…"）
2. **口号与比喻不进结构位置。**（"等于没来" / "一眼千年" / "此生必去"）
3. **不描述自己的结构。**（"这一节讲什么" / "下面所有的…" —— "下面"是哪？）

## 7. 顺手要避开的七类语言毛病

1. **不要描述自己的结构** —— 别写"下面所有的『值得去吗』都给答案"。直接说事。
2. **不要用与页面对不上的词** —— 例：写"**方框**中标『未核实』"，但页面上其实是文字行，根本没有方框（该标记本轮起已不上页面）。**文案要对着实际渲染写。**
3. **同一概念全篇用同一个词** —— 别一会儿"景点"、一会儿"打卡点"、一会儿"点位"。
4. **不要写"我们"** —— 攻略是给读者的交付物。用"建议""注意""可以直接…"这类无人称句式，不要出现"我们认为""我们推荐"。
5. **不要用大众看不懂的缩写与行业词** —— 读者是普通游客，**必须写大众认识的名字**。
6. **不要把"核验状态"写成"提醒"** —— 两者是两个角色，见下。
7. **不要把"我们怎么做"写上页面** —— 例：小红书入口文案曾写「小白出片」，那是**我们起搜索词时的站内黑话**；
   用户判定"这种词不能出，原本是我们的制作思路"。**凡是"我们内部怎么得出的"，读者面前一律不出现。**
   与第 6 条的区别：第 6 条是**把状态当提醒**，这条是**把内部方法当文案**。

### 5 的落地：术语黑名单（写"人话名字"）

> **Q39 用户判定**：出发前必做事里出现了 **`OTA`** —— *"这种大众看不懂的词，要写大众认识的名字"*。

| ❌ 缩写 / 行业词 | ✅ 写成大众认识的名字 |
|---|---|
| `OTA` / `OTA 平台` | **`携程、飞猪、美团这类订票平台`**（举例比造词清楚） |
| `POI` | **`地图上的地点`** / **`地图搜索里搜到的店`** |
| `WebService` | **`地图接口`**（只在与用户确认 Key 时用技术词，页面上不出现） |
| `UGC` | **`网上别人的分享`**（注意：UGC 内容**本来就不出处在页面上**，见 `verification.md`） |
| `实时路况` | **`当前堵不堵`** |
| `小白出片` 等平台站内黑话 | **`小红书·拍照参考`** —— 黑话属于"我们的制作思路"，不上页面（见 §7-7） |
| `实名预约` | 可保留（政务/景区通用语）；但**必须紧跟一句"怎么约"** |
| `入境` / `落地签` 等出境专有词 | 首次出现时用一句话解释（本 skill 以境内行为主） |

**判据**：**这个词，一个不常出门的人读得懂吗？** 读不懂 → 换成它指的那件事。

### 6 的落地：核验行是状态，「提醒」是给读者的动作

> **Q39 用户判定**：预算构成里的 **"未核实"** —— *"应该换成『提醒』。未核实是状态，这里其实是传递信息提醒"*。

| 角色 | 它回答的问题 | 长什么样 | 用在哪 |
|---|---|---|---|
| **核验行**（`.vf`） | **这条信息我核过没有？** | `✅ 已核验（基于{来源大类}）` —— **只有这一种**；没有标记 = 推断或经验 | 每日行程的餐饮节点下、避坑 hard 条目下 |
| **提醒**（`.say`） | **看到这条，我该做什么？** | 浅赭金底 + 3px 赭金竖条 + `<b>提醒</b>` | 预算构成、天气与行李等**估算类信息**之后 |

> ⚠️ **不要把两者混用**：估算类信息**没有"核实"这回事**（它本来就是估算），
> 所以它需要的是**一句提醒**（"以 5 人合计计 / 高铁票价按二等座估 / 具体以购票页为准"），
> 而**不是一个"未核实"的灰标**（这类灰标已不上页面）—— 那个灰标在这位置既不通顺、也没给读者任何动作。
