## 1. 一句话

**让每一段内容都长成"一个有边界的块"，并且让读者在三秒内知道这个块讲什么。**

排版的全部工作就是这一句。做到这句话，页面自然不难看。

## 2. 颜色体系

**规则：一套颜色只背一个语义。** 一个颜色如果在页面上同时表示两件事，读者就学不会它。

| 层 | 令牌 | 值 | 只用来表示 |
|---|---|---|---|
| 底 | `--paper` | `#f2efe7` | 页面底色（暖纸） |
| 底 | `--paper-alt` | `#fbfaf5` | 交替章节底（分区用） |
| 底 | `--card` | `#ffffff` | 内容块（白） |
| 墨 | `--ink` | `#1b2a21` | 章节标题 / 章节编号药丸 / 深色块 |
| 正文 | `--text` / `--text-soft` | `#26332b` / `#4a594f` | 正文 / 次要正文 |
| 注释 | `--muted` | `#6d7b72` | 元信息、页脚说明、字段名 |
| **主色** | `--jade` / `--jade-deep` / `--jade-soft` | `#2f7d5c` / `#21573e` / `#e4efe8` | 见下方「青绿的语义边界」 |
| **辅色** | `--gold` / `--gold-soft` | `#a8791f` / `#f8f0dd` | **数字 / 标题装饰 / 判断结论 / 提醒行** |
| **警示** | `--alert` / `--alert-soft` | `#b3261e` / `#fceceb` | **只给「必读」暗红点**（药丸已废 · Q42） |
| 分组 | `--g-spot` | `#2F5D7E` 石青 | 🏛 景点组（白字对比 7.0:1） |
| 分组 | `--g-food` | `#B5502A` 朱磦 | 🍜 美食组（5.1:1） |
| 分组 | `--g-hotel` | `#6B4A73` 紫檀 | 🏨 住宿组（7.4:1） |
| 分组 | `--g-trans` | `#3A6E78` 沧浪 | 🚇 交通组（5.7:1，与主色青绿拉开色相） |
| 分组 | `--g-photo` | `#A83A5C` 胭脂 | 📸 打卡组（6.1:1） |
| 品牌 | `--xhs` | `#ff2442` | 只给小红书按钮 |

### 硬约束

1. **主色（青绿）不得用于无语义装饰。** 它一变装饰，读者就分不清"能点"和"不能点"。（边界见下。）
2. **辅色（赭金）不得用于大色块。** 它只点缀数字与小标题。
3. **警示红只给「必读」那个点。** 页面上一共只有两处地方会出现红：**必读的暗红点**、小红书标签的品牌红点。**不得让别的东西也红**，否则「必读」就不再是最高优先级。
   🔧 **Q42 定稿**：**文字徽标（药丸）整体废弃** —— 用户判定 *"观感不好，直接不要这个标签"*。
   现在只是**标题前一个 8px 点**：`hard` = `--alert` 暗红、`soft` = `--gold` 暗黄。**点放在信息前**。
   ⚠️ **这条是对硬约束 8（"不靠颜色单独传意"）的显式例外**，代价写明：**色觉障碍者难以区分两档** ——
   兜底靠**组内排序**（`hard` 一律排在前面）+ **条目文字本身**（"必须提前实名预约"本就是硬信息）。
   用户明示选择此形态，故记为例外，不视为违规。
   🔧 **Q39 留痕**：药丸曾从"实心红铺底"降到"浅红底 + 深红字 + 淡红描边"，本轮再被整体去掉。
4. **分组五色承载固定语义（🏛 景点 / 🍜 美食 / 🏨 住宿 / 🚇 交通 / 📸 打卡）**，只能以这个语义出现（必读指南分组色块、每日行程的同类标记）；**不得作无语义装饰**。**五色只用上表的"国画矿物色"值**——曾用 Tailwind 高饱和五色（`#2563EB` 钴蓝等），与青绿/赭金/暖纸的纸本体系是两套色系，同页打架；矿物色降饱和后与主体系同族，且白字对比全部 ≥4.5:1。
5. **正文对比度 ≥ 4.5:1**，大字号（≥24px）≥ 3:1。
6. **不靠颜色单独传意**——凡是靠颜色区分的，必须同时有图标或文字。（分组色块同时有 emoji + 组名。）
7. **赭金（3.87:1）只做装饰与 ≥18px 粗体强调**（竖条 / 数字 / 小节标题），不得用于正文或小字。
8. **小红书红 `#ff2442` 是品牌色豁免**（3.76:1），只出现在品牌按钮上，不得挪作他用。
9. **颜色预算：一张卡上带颜色的元素最多 2 处。** 其余一律中性（墨 / 灰 / 暖纸）。
   **理由**：颜色的指向性来自稀少 —— 给两处，读者知道该看哪里；给六处，颜色就退化成装饰，读者全部忽略。

### 青绿的语义边界（三档，Q30 写明）

青绿是本页最稀缺的资源，**分三档用，不得混用**：

| 档 | 形态 | 只用来表示 | 出现在 |
|---|---|---|---|
| **实心青绿** | `--jade` 填充 | **可点 / 当前** —— 全页唯一暗示"这个能点"的信号 | 目录当前项 |
| **浅青绿底** | `--jade-soft` + 4px 青绿竖条 | **我们的判断 / 提示**（不可点） | 每日安排思路 `.whyline`、倾向徽标「值得」 |
| **青绿描边** | 1px `--jade` 边框 | **次级提示 / 可点暗示** | 倾向徽标「值得」、芯片 hover 态 |

> ⚠️ **已知例外（保留，理由写明）**：倾向徽标「**必去**」用**实心青绿**。它严格说不可点，但它是**整张卡的唯一结论**，且带文字、位于卡内、不参与导航 —— 混淆风险低于"把唯一结论染成弱色"的代价。
>
> **备选方案（未采用 · 默认按上方四色生成，无需动作）**：把倾向四色整族改成**赭金族**（必去 = 实心赭金 / 值得 = 浅赭金 / 可选 = 描边 / 可跳 = 灰），青绿就**纯粹只表示"能点"**。用户若想换，**改这一处即可**，无其他联动。

## 3. 字号阶梯

**规则：全篇字号只有一个入口——`--fs-*` 变量。模板里已经做到零裸值（`font-size:` 后面必须跟 `var(--fs-…)`）。**

这套阶梯是**成比例的**：以正文 17px 为基准，每上一档放大 ~1.1–1.2 倍；且**相邻两档必须同时满足"数值拉开 ≥1.5px"或"字重不同"**，否则读者看不出层级。

| 变量 | 值 | 角色 | 字重 | 行高 |
|---|---|---|---|---|
| `--fs-cap` | `clamp(34px,6.4vw,54px)` | 封面主标题 | 800 | 1.32 |
| `--fs-sec` | `clamp(25px,3.3vw,31px)` | 章节标题 `h2` | 800 | 1.32 |
| `--fs-sub` | `22px` | 小节标题 `h3` / 每日「第 N 天」 | 700–800 | 1.32 |
| `--fs-title` | `20px` | 卡片标题：景点名 / 每日日期 | 700–800 | 1.32 |
| `--fs-lead` | `18px` | **强调正文**：理由句 / 事实数值 / 分组标题 / 必读条目名 / 卡片小标题 | 700–800 | 1.5 |
| `--fs-body` | **`17px`** | **正文（基准）**：段落 / 列表 / 目录项 / 步骤 | 400–600 | 1.8 |
| `--fs-note` | `15.5px` | 次要说明：表格 / 步骤时间 / 页脚 / 事实芯片 / 行动按钮 | 400–800 | 1.7 |
| `--fs-label` | `14px` | 标签 / 芯片字段名 / 表头 / 核验行 | 600–800 | 1.5 |
| `--fs-mini` | `13px` | **仅图内文字**（脑图 SVG）——全篇下限 | 400–700 | 1.4 |

### 硬约束

1. **不得出现裸字号数值。** 新增元素一律从上面挑一个变量；确需新档，先加进本表并说明理由，再进 `:root`。
2. **全篇下限 13px**，且只许出现在图内文字；**页面正文类不得低于 14px**。需要靠缩小字号塞内容，说明这一块该拆了。
3. **档与档必须能一眼分辨。** 上一版的病根是：小节 20px 与景点名 21px 只差 1px 且同为 700 —— 读者当成同一级，页面就显得"扁平"。**相邻档不许既差 <1.5px 又同字重。**
4. **一个块内最多三个字号**（标题 / 正文 / 元信息）。**标签内部只能有一个字号** —— 值要突出靠字重，不靠放大缩小。
5. **行高：正文 1.8，标题 1.32。** 正文行高低于 1.7 会变成"文字墙"。
6. **一行 35–40 个汉字（手机）／50–70 字（桌面）。** 超过就把容器收窄（`max-width:66ch`）。
7. **强调只能靠"加大 + 加深 + 加粗"三件事**，不得用斜体、下划线、彩色文字。
8. **强调必须稀有。** 一屏里到处都强调，等于没有强调。

## 4. 块状阅读

**规则：每个语义单元必须是一个有边界的块；块与块之间的距离，必须明显大于块内部的距离。**

依据是格式塔的**接近性原则**——读者靠"距离远近"判断"哪些是一起的"。

### 间距阶梯（不得随手定值）

| 位置 | 值 |
|---|---|
| 块内文字行距 | 行高 1.8 |
| 块内元素间距（标题↔正文） | 8–12px |
| 块内边距（padding） | 18–22px |
| **块与块之间** | **18–24px** |
| 小节标题上下 | 34px / 14px |
| **章节之间** | **margin-top 56px + 内边距 34px** |
| 页面左右留白 | 桌面 24px ／ 手机 16px |

### 块状阅读的六条硬约束

1. **白底 + 1px 边框 + 微投影，三者缺一不可。** 只靠空行分隔的纯文字，读者不会感知成一个"块"。
2. **相邻章节交替底色**（`--paper` / `--paper-alt`），并把章节包成一个描边白块。区块感靠"底色 vs 白块"的对比来立，不靠画更多线。
   ⚠️ **例外（有意为之）**：景点 / 每日行程 / 必读指南这三节**同为 `alt`** —— 它们装的全是**白卡**，
   白卡需要交替底才立得起来。**交替的目的是"让白卡与背景拉开"，不是机械地隔一节一换。**
3. **章节 = 序号药丸 + 标题，直接进内容；🔧 不得写章节导语**（Q30 废止）。
   ~~原据："每个章节必须有标题 + 一句话导语，导语回答这一节讲什么、我该不该看。"~~
   **废止理由**：这类导语（例：`这一页看完就能走完整个行程 —— 值不值得去，给答案；怎么去，给材料`）**是写给制作者的，不是写给读者的** —— 它在页面上占地方，还把"这份攻略该怎么用"这类元信息混进正文；读者点开目录就知道要看哪一节。
   **现行**：给读者的话只写**具体的事**（景点理由、避坑条目、当天动线），不写"这一节讲什么"。文案判据见 `writing-style.md` §4。
4. **一个块只讲一件事。** 块内超过 6 条并列项，拆成两个块。
5. **块有三种强度，全篇只用这三种**：
   - **普通块**：白底 + 1px 边框 + 微投影
   - **提示块**：浅色底（青绿 or 赭金 8–10%）+ **左侧 4px 实色竖条**
   - **警示块**：浅红底 + 左侧 4px 红竖条（**只给「必读」暗红点**；🔧 Q39 前是给旧 emoji 徽标）
   > ⚠️ **不得给"普通块"加装饰性顶边 / 彩条**（Q30 修：事实卡曾有一条 `4px` 青绿顶边，属无语义装饰，已删）。
6. **一张卡片的阅读顺序固定**：视觉锚点（实景图）→ 标题 + 倾向徽标 → **一句话**（**卡面不出现字段名**，与倾向徽标同属「一眼判断区」，Q40）→ **小提示** → 事实芯片 → 状态行 → （**卡外**）**`小红书·游玩攻略` / `小红书·拍照参考`** 两个标签。**顺序不要调换**——读者的视线就是从左上扫到右下。

### 分类块版式（必读指南专用）

必读指南的五个分组**不是普通卡片**，它们的顶部长着一张**分类实景图**，用来替组名说话。

| 项 | 做法 | 理由 |
|---|---|---|
| 布局 | ★ **两栏瀑布流（masonry）**：`columns:2` + `break-inside:avoid`；`≤1000px` 降为单栏 | 五组内容**长度本来就不一样**（景点组常 4 条、打卡组常全是提示）。用 `grid` 会**把两列拉成等高**，短的那组下方留一大块空白 —— 用户实测报的就是"左右卡面长度不对称"。瀑布流让**每组各自顶到上方** |
| 组头 | 顶部一张**分类实景图**（高 130px，`object-fit:cover`） | 用"这一类长什么样"替代色块底 —— 读者看图就懂，不用先读字 |
| 渐淡 | 图的下缘用**白色线性渐变**（50% → 84% → 100% 不透明度）融入卡面 | 硬切边会让图看起来像"贴上去的"；渐淡让图和卡面是**一张纸** |
| 组名 | 压在**渐淡之后**的位置（`bottom:7px`），墨色 `--ink` + 组 emoji + `N 条` | 字必须落在已经变浅的区域上，深字压浅底才清楚 |
| 分组语义色 | 只用组名前的 **9px 色块**（`--g-spot` 等） | 色块底是上一版的病根：五块不同色的底堆在一页 = 花。**一套颜色只背一个语义，不铺面积** |
| 空组 | **不渲染**（连图一起省） | —— |

> ⚠️ **不要在图上做渐变**（生图时写"底部渐淡"出不来可控的结果）。**渐淡是 CSS 的活**，见模板 `.pfhead::after`。

## 5. 框线与圆角

**规则：框线是"块的边界"，不是装饰。它必须被看见，但不得抢戏。**

| 用途 | 令牌 | 值 |
|---|---|---|
| 卡片 / 章节 / 表格外框 | `--line` | `#b6c4ba`（白底上约 2:1，可见但不刺眼） |
| 块内分隔（虚线） | `--line-hair` | `#d5ded8` |
| 强调边界（左侧竖条） | 语义色 | 3–4px 实色 |
| 章节标题底线 | `--ink` | 2px |

### 硬约束

1. **禁止浅于 `--line` 的边框。** 上一版用 `#e1e6e0`（对比约 1.25:1），在白底上几乎不存在——这就是"框线过浅过细"的成因。
2. **禁止 0.5px / 1px 以下的描边。**
3. **块内分隔用虚线、块的边界用实线。** 两者混用会让层次消失。
4. **圆角分三级，不得混用**：
   - 倾向徽标 / 小标签：`8px`
   - 卡片 / 提示块：`14px`
   - 章节 / 景点卡 / 每日卡：`20px`
   - 药丸（标签芯片、按钮）：`999px`

## 6. 标签体系

**规则：标签按「角色」分层 —— 一个角色只用一种形态。角色数量固定，不得新增。**

### 翻车现场（Q30 实测，本节的由来）

一张景点卡上同时站了 **6 类**标签：倾向徽标 / 疑问式标签 ×2（`值得吗`、`代价是什么`）/ 妙计前缀标签 / 事实芯片 ×4 / 核实行 / 行动按钮。**形态各异、字号不一、颜色各异、信息量从 2 字到 22 字** —— 读者的眼睛找不到落点，看起来就是"乱"。

### 五个角色（固定槽位）

| 角色 | 槽位 | 形态 | 字号 | 颜色 | 信息量上限 |
|---|---|---|---|---|---|
| **① 主张标签** `.spot-tag` | 压在实景图**左下角** | 深色毛玻璃药丸（墨 78% + 模糊），**内部只放两段文字，无图标** | 主段 `--fs-lead` / 副段 `--fs-label` | 主段赭金 `#e8c88f` + **衬线 800**；副段白 84% + **无衬线 500 + 字距 .10em** | **固定两段**：`{费用}` `{定性}`，合计 ≤16 字 |
| **② 倾向徽标** `.stance` | 景点名**右侧** | 药丸（实/浅底 + 描边） | `--fs-label` | 青绿族 / 赭金族（见下表） | **一个词**：必去 / 值得 / 可选 / 可跳 |
| **③ 事实芯片** `.chip` | 卡体**底部** | 浅底 + 1px 细框药丸 | `--fs-note` | **中性**：字段名灰 600 + 值墨 800 | 每条 ≤14 字；**一卡 ≤4 条**；字段名限字典 |
| **④ 小提示** `.spot-tip` | 卡体**最底部** | 浅赭金底 + 左侧 3px 赭金竖条 | `--fs-body` | 前缀「小提示」赭金深 `#7d5a12` 800；正文 `--text` | **必去 ≤40 字（≈2 行）／值得 · 可选 ≤20 字（≈1 行）**；**一卡最多一条** |
| **⑤ 严重度点 + 核验行** `.pfi.hard` / `.pfi.soft` / `.vf` | 条目标题前 · 条目行内 | **8px 圆点**（暗红 / 暗黄，**只有色相不同**）/ **纯文字行** | `--fs-label` | 语义色 / 灰 | **核验行只有"✅ 已核验（基于X）"一种**；"未核实"不上页面 |
| **⑥ 提醒行** `.say` | 块内**末尾**（预算表下等） | 浅赭金底 + 左侧 3px 赭金竖条 | `--fs-body` | 前缀「提醒」赭金深 `#7d5a12` 800；正文 `--text` | **一句话**；只用于**给读者的行动提示**，**不得**用来声明核实状态 |
| **⑦ 口诀标题** `.jingle` | 卡片**首行** | 无底无边，**衬线 + 字距 `.06em`** | `--fs-lead` 800 | `--ink` | **6–12 字、两顿对称**；只用于「游玩要点」 |

**为什么主张标签里一个图标都不放（Q31）**：它的两段文字已经用**两层手段**分了主次 —— "衬线大字 + 赭金"对抗"无衬线小字 + 白色 + 字距"。再塞一个圆点或 emoji，就是**第三层冗余**：读者要多解析一个不承载信息的图形，标签反而更难读。**分主次靠字型与颜色，不靠加东西。**

**事实芯片的字段名字典（不得自造）**：
`门票` / `时长` / `开放` / `预约` / `交通` / `位置` / `人数限制` / `排队`
—— 字典之外的信息**归入正文**，不要硬塞进芯片。

> 🔧 **Q39 废止「字段块」（`.qa`）与「妙计」（`.tac`）**：它们承载的是「值得的理由」与「战术提示」两段**并列段落**。
> 用户判定景点卡"**没有卡的感觉、内容太多**" → **两个形态整体删除**。
> 「值得的理由」的职能**并入 `.why` 一句话总结**（它本来就是"值得去的理由"）；「妙计」**并入 `.spot-tip`**（小提示）。
> **教训**：一种角色只要装得下**第二个段落**，卡片就从"一眼看懂"退化成"要读完" —— 卡片的敌人不是信息量，是**并列段落**。

> ★ **优缺点的权重不对称（Q31 定）**：**主张在上（图上的主张标签 + `.why` 一句话总结），避坑在下（`.spot-tip` 一行）。**
> 上一版把"值得的理由"与"付出的代价"做成两个**并列等权**的字段块 —— 结果缺点和优点一样大声，一张卡读起来像在犹豫。
> 现行：**主张占整张卡的上半，避坑只占最后一行**。缺点不是不说，是**降权说** —— 读者该先被打动，再被告知风险。

### 倾向徽标的四种形态（不得自由配色）

| 倾向 | 底 | 字 | 强度 |
|---|---|---|---|
| **必去** | 实心青绿 `--jade` | 白 | 最强 —— **全卡唯一实心** |
| **值得** | 浅青绿 `--jade-soft` + 青绿描边 | `--jade-deep` | 次 |
| **可选** | 浅赭金 `--gold-soft` + 赭金描边 | `#7d5a12` | 弱 |
| **可跳** | 暖纸 `--paper` + `--line` 描边 | `--muted` | 最弱（灰） |

> **只有「必去」是实心的。** 实心是这张卡最稀缺的资源，一页里给多了就不稀缺了。

### 其他位置的结构标记（沿用，不得新增）

| 位置 | 做法 |
|---|---|
| 章节标题 | 左侧编号药丸（`01`–`05`，**墨底白字**——不用青绿，青绿留给"能点"） |
| 小节标题 | 左侧 4px 赭金竖条 |
| 块标题（事实卡等） | 左侧 9px 圆角色块（**同一类块用同一颜色**） |
| 分组色块标题 | 实色药丸 + 组 emoji + 条数（`🏛 景点 3 条`） |

### 硬约束

1. **一个角色只用一种形态。** 不要在 A 卡用实心药丸表达倾向、在 B 卡用色底文字表达 —— 同角色不同形态，读者就得重新学一遍。
2. **标签不是段落。** 标签内**不得出现句号**、不得换行、**不得塞整句**。写不下 → 归正文。
3. **标签内只有一个字号。** 值要突出靠**字重**（600 → 800），**不靠缩小或放大字号**。（上一版的病根：芯片里套 `<b>` 并把字号从 `label` 跳到 `note`，芯片内部自成两级。）
4. **药丸里不再嵌同色小方块。** 已经是一枚有颜色的药丸，再嵌一个同色方块 = 纯装饰。
5. **不用标签承载"问题"。** `值得吗` / `代价是什么` 这类**疑问式**文字**不得做标签**。**`付出的代价` 不做字段块**（Q31 降权为 `④ 小提示`）；**`值得的理由` 也不做字段块**（Q39 并入 `.why` 一句话）。
6. **图标 / 色点只做识别，不做装饰。** 加个色点却不承载分类信息，就是噪音。**主张标签内一个图形都不放**（Q31，理由见上）。
7. **同一语义全篇同一颜色**，不得一处青绿、一处赭金。（事实卡的五张是同一类块 → 色点**统一赭金**，曾用青绿/赭金交替 = 自相矛盾。）
8. **不靠颜色单独传意** —— 靠颜色区分的必须同时有文字。（分组色块同时有 emoji + 组名。）
   ★ **唯一例外：避坑严重度的两个点**（暗红 / 暗黄）—— 用户明示选择此形态，代价与兜底见 §2 硬约束 3。
9. 分组 emoji 固定五件套：🏛 景点 / 🍜 美食 / 🏨 住宿 / 🚇 交通 / 📸 打卡。
10. 状态类标志固定：避坑严重度 = **标题前 8px 点**（暗红 = 必读 / 暗黄 = 提示）；核验行 = **`✅ 已核验（基于{来源大类}）`**，且**只有这一种**。
    🔧 **Q42 改形**：药丸形式的「必读 / 提示」已废（用户判定"观感不好，直接不要这个标签"）；"未核实"标记不再出现在页面上。
    🔧 **Q39 留痕**：原为「🚨 会毁行程」「💡 体验提示」→ 四字带 emoji 太抢，改两字固定文案。

> 景点卡顶部的**实景图**不是图标，是视觉锚点。生成规格见 `spot-images.md`。

## 8. 悬浮反馈

**规则：浮动反馈只给"有明确交互"的元素。**

位移是一种**承诺**——元素一动，读者就读作"这里能点"。所以：

| 给 | 不给 |
|---|---|
| 可跳转的按钮 / 链接（目录项、**景点卡外的两个小红书标签**） | **纯内容容器**（普通块 `.card`、每日卡 `.day`、分组块 `.pfgroup`、**景点卡 `.spot` 本体**） |
| 行程总览的**头一行事实卡** `.fact`（摘要条，唯一例外） | **纯展示的标签**（事实芯片 `.chip`） |
| 行程总览的**头一行事实卡** `.fact`（摘要条，唯一例外） | 封面图（第一眼要静） |

> Q31 收窄的理由：上一版给了 9 类元素浮动 —— 一页里到处在动，读者的鼠标划过哪里哪里抬起来，**"动"就不再是信号**。而且内容块抬起来却点不动，是**假可供性**（false affordance），会让读者做无效点击。**能动的东西必须真的能点。**

它解决的是**"这页是活的"**这件事：读者的鼠标移上去，元素轻轻抬起来回应一下，页面就从"一张图"变成"一份东西"。

### 规格

| 元素 | 动作 | 值 |
|---|---|---|
| 景点卡内的实景图 | 微放大（**触发者是整格 `.spotcell`**） | `scale(1.05)`（父容器须 `overflow:hidden`） |
| 行程总览头一行 `.fact` | 上浮 + 描边转青绿 | `translateY(-2px)`（**唯一允许浮动的纯展示块**） |
| 目录项 `.toc a` | 右移 | `translateX(3px)` |
| 小红书标签 `.xhs` | 上浮 + 品牌红阴影 | `translateY(-2px)` |
| 脑图外框 `.mindwrap` | **只换边框色**（不位移） | `border-color → --jade` |

**以下元素明确不给浮动**（Q31 从旧版移除 / Q39 追加）：普通块 `.card`、每日卡 `.day`、分组块 `.pfgroup`、
事实芯片 `.chip`、封面图、**景点卡 `.spot` 本体**。

> 🔧 **Q39 追加 `\.spot` 的理由**：小红书两个标签已移到**卡外**，卡内**再没有任何可点元素** ——
> 这时卡整张浮起来就是在承诺"点我"，属**假可供性**（P22）。
> **判据可复用**：一个容器要不要给位移，看的不是"它像不像卡片"，而是"**它的边界内有没有可点的东西**"。

### 硬约束

1. **必须整体包在 `@media (hover:hover)` 里。** 触屏设备上裸 `hover` 会"粘住"——手指点过之后那一块一直保持浮起状态，看起来像坏了。
2. **只动 `transform` 与 `box-shadow`，不得动尺寸**（`width/height/padding`）。动尺寸会引发重排 → 相邻元素抖动。
3. **位移不超过 4px。** 超过就不再像"纸被掀起一角"，而像幻灯片飞入。
4. **过渡时长：位移 0.25s、图片 0.6s**，缓动统一 `--ease`（`cubic-bezier(.22,.61,.36,1)`）。图比卡慢，才有"带动"的层次。
5. **`prefers-reduced-motion: reduce` 下必须全部关掉**（模板已用 `*{transition:none!important}` 覆盖）。
6. **移动端不补替代动效。** 手机上手指遮挡画面，浮起无意义，不加。
7. **加浮动前先问一句：这个元素点得动吗？** 点不动就不给位移。（`.fact` 是唯一例外，因为它承担"摘要条"的角色，横向一排浮起有"成组"的观感。）

## 9. 响应式断点

只有两个断点，不要加更多。

| 断点 | 变化 |
|---|---|
| `≤1000px` | 左目录 → 顶部横滑标签条（sticky + 毛玻璃）；事实卡 5 列 → 2 列；**必读指南两栏 → 1 栏**；各网格 → 1 列 |
| `≤620px` | 页面留白 24 → 16px；章节内边距收紧；景点图 212 → 178px；每日页脚 → 1 列 |

**规则**：手机端**不重排信息顺序**，只重排列数。读者在手机和电脑上看到的章节顺序必须一致。

## 10. 改模板时的检查清单

复制以下清单，逐项核对：

- [ ] **所有 `font-size:` 后面都是 `var(--fs-…)`**，模板里零裸值
- [ ] 新增的字号在 §3 表内，没有引入新数值
- [ ] 相邻两档字号**既不是差 <1.5px 又同字重**（能一眼分辨）
- [ ] 新增的颜色在 §2 表内，没有引入新语义
- [ ] 新块同时有：白底 / 1px `--line` 边框 / 微投影，**且没有装饰性彩条**
- [ ] 块间距 ≥ 块内间距的 2 倍
- [ ] 新的可点元素高度 ≥ 44px
- [ ] 新块的标题有图标或色点，**且同一类块用同一颜色**
- [ ] 没有小于 14px 的页面文字（图内文字可到 13px）
- [ ] **章节没有导语**（不得出现"这一节讲什么"式的说明）
- [ ] **标签按 §6 角色表落槽**：一个角色一种形态；事实芯片 ≤4 条、每条 ≤14 字、字段名在字典内
- [ ] **一张卡上带颜色的元素 ≤2 处**（颜色预算）
- [ ] **药丸里没有再嵌同色小方块**（无纯装饰图形）
- [ ] **新增的悬浮反馈写在 `@media (hover:hover)` 内，且只动 `transform` / `box-shadow`**
- [ ] **新增浮动前问过"这个点得动吗"**（点不动的元素不给位移，`§8` 硬约束 7）
- [ ] **必读指南是两栏瀑布流（`columns`）+ 每组一张分类图**，空组不渲染，分组色只出现在 9px 色块里
- [ ] **景点卡没有「值得的理由」字段块、也没有「妙计」块**，只有 `.why` 一句话（**卡面不出现字段名**）+ 底部一行 `.spot-tip`（小提示）
- [ ] **景点卡三组都进了两列网格**（`.grid.g2.spotgrid`），小红书两个标签在**卡外**下方并排（`.xhsrow`），文案是 **`小红书·游玩攻略` / `小红书·拍照参考`**（**不得出现「小白出片」等站内黑话**）
- [ ] **「天气」卡恰好三行**（白天 / 夜间 / 天气总结），标题是「天气」，**没有第 4 行小字**
- [ ] **同排两张景点卡的高度差 ≤3 行**（正文上限：`why` ≤1 行 / `tip` 必去 ≤2 行、值得·可选 ≤1 行 / 芯片 ≤4 条）
- [ ] **每日行程每天一块内嵌路线图**（无 Key 则整块删）；**行程全貌里没有地图**；**图位标题只写「今日动线」**（不用文案复述图里画了什么）
- [ ] **提醒行 `.say` 只做行动提示** —— 没有把核验行当提醒用（状态与提醒是两个角色）
- [ ] 用「眯眼看」检查：模糊后最重要的元素仍然最先跳出
- [ ] 全篇强调不超过 3 种手段
- [ ] `prefers-reduced-motion` 已覆盖动画

| **分主次靠字型与颜色，不靠加图形**：主张标签两段文字用"衬线大字 + 无衬线小字 + 双色"分层，无图标 | 用户指示（Q31「用无图标，金色字体 + 不同字型即可」）；用户样本网页的 `.spot-tag` 亦为纯文字药丸（`.free` 段单独给金色） |
| **内容容器不给浮动**：位移 = 可点的承诺，点不动就是假可供性 | 用户指示（Q31「可浮动部分过多…其他不浮动」）；可用性常识（affordance / false affordance） |
| **缺点降权**：避坑做成卡底一行，而不是与优点并列的字段块 | 用户样本网页实测结构（Q31）：它把优点做成图上标签 + 正文，缺点压成 `.spot-tip` 一行 —— **权重不对称**，读者先被打动再被告知风险 |
| **景点卡三组统一进两列网格**：大卡不再独享整行；同排卡片高度差 ≤3 行 | 用户指示（Q39「大卡没有卡的感觉，需要和小卡一样做成左右两个卡排列…卡稍微加长但最多 3 行」） |
| **两栏瀑布流（`columns`）**：长度不等的分组各自顶到上方，不强求等高 | 用户指示（Q39「左右卡面长度不对称…下方的卡面顶上来，不必强行对称等另一个卡显示完」） |
| **严重度徽标降醒目**：实心红 → 浅红底深红字，与倾向徽标同形不同色（Q39，后被 Q42 取代） | 用户指示（Q39「会毁行程很突兀…框也要调的没这么醒目，和上面景点卡的标签框以及字体风格保持一致」） |
| **严重度从"文字徽标"改为"一个点"**：药丸整体去掉，标题前 8px 暗红 / 暗黄，放在信息前 | 用户指示（Q42「必读/提示标签观感不好，直接不要这个标签；必读改暗红点、提示改暗黄点，都放在信息前」） |
| **状态 ≠ 提醒**：核实状态（声明核过没有）与行动提示（告诉读者怎么做）是两个角色 | 用户指示（Q39「未核实是状态，而这里其实是传递信息提醒」） |
| **可点标签移出卡片后，卡本体不再给位移** | 本项目 P22（假可供性）的推论（Q39）：判据 = "容器边界内有没有可点的东西" |
